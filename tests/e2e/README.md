# E2E smoke (jsdom)

Прогоняет настоящий `app.js` против живого сервера: лента, вопрос, вход через форму,
редактирование, поиск, подписки, уведомления, голосование (+5/−1 автора, ±1 остальных), ответ, холивар, комнаты, профиль,
мод-панель и все вкладки админки. Сценарий меняет данные, поэтому запускай на свежей БД.

```bash
./scripts/reset_dev_db.sh
DATABASE_URL=$(.venv/bin/python scripts/dev_pg.py) REDIS_URL=memory:// DEMO_MODE=1 ANTIBOT_DISABLED=1 \
  .venv/bin/hypercorn app.asgi:asgi_app --bind 127.0.0.1:8001 &
cd tests/e2e && npm i jsdom@24 && NODE_PATH=$PWD/node_modules node smoke.js
```

Дополнительно `node clubs.js` (тот же сервер и jsdom) проходит путь игрока по кооперативам: основание клуба
через диалог, вступление вторым участником, тег клуба у ника, уход за Гриб-Танком и личный кулдаун, автособытие
и пост в ленте, а также админскую вкладку «Клубы» с дебагом Танка. Скрипт идемпотентен: старые клубы уводит
в музей через админский PATCH и пополняет кошелёк демо-средствами (`POST /api/clubs/dev/grant` — роут живёт
только при `DEMO_MODE`).

Дополнительно `node ui_checks.js` (тот же сервер и jsdom) проверяет мобильный наклон жидкости
(авто-включение датчика без нажатия, фолбэк-кнопку при iOS/без показаний датчика, отказ в разрешении),
отсутствие кнопок музыки, аватар в меню (буква без аватара, картинка после загрузки с рамкой профиля
и возврат к букве, если файл не догрузился) и «идеальный коридор» показателей гриба: зелёные зоны ровно по
диапазонам с сервера, оранжевая полоска вне зоны, плашка «⚠️ пересластил / мало заварки / … — опыт ×0.5»,
тосты «+2 опыта» в коридоре и «+4 опыта (×0.5 — вне коридора)» после перекорма, строка о коридоре
в админской панели мутаций. Состояние гриба dasha скрипт выставляет сам через админский PATCH,
поэтому его можно запускать повторно на любой базе.
